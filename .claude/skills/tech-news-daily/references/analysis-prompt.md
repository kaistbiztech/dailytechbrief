# 기사별 '알기 쉽게 읽기' 분석 작성 지침

입력: `data/<id>.json` (그날 호 10건). 출력: `data/analysis/<id>.json` 하나.
`scripts/article_pages.py`가 이 JSON으로 `date/<id>/<NN>/` 페이지를 만든다.

## 반드시 지킬 것

1. 각 기사의 `sources[].url` 원문을 **WebFetch로 직접 읽는다**. 사실(숫자·이름·날짜·인용)은 원문에 있는 것만 쓴다.
2. 원문을 못 읽으면(차단·유료벽·404) 그 기사는 `"basis": "clip"`으로 두고, 그날 호의 `summary`에 있는 내용 범위에서만 쓴다. 페이지에 '원문 요약 기준' 배지가 붙는다.
3. 지어내지 않는다. 원문에 없는 전망·수치·인물 발언을 넣지 않는다. '왜 중요한가'·'더 생각해 볼 점'은 해석이지만 원문 사실에 기대어 쓰고, 단정 대신 "~할 수 있습니다"로 쓴다.
4. 클리핑(`summary`)과 원문이 다르면 원문을 따르고, `notes`에 한 줄로 남긴다.
5. 쉬운 존댓말. 전문용어는 처음 나올 때 풀어 쓴다. 달러는 원화를 같이 쓴다(기사에 환산값이 있으면 그 값, 없으면 1달러≈1,340원 어림, 앞에 '약').

## JSON 형식

```json
{
  "id": "YYYY-MM-DD",
  "generatedAt": "ISO8601+09:00",
  "generator": "작성 주체",
  "fxNote": "원화는 기사에 적힌 환산값을 우선 쓰고, 없으면 1달러≈1,340원으로 어림했습니다.",
  "articles": [
    {
      "order": 1,
      "basis": "original",
      "oneLine": "한 줄 요약(1문장)",
      "what": ["무슨 일인가 문단 1~3개"],
      "background": ["배경·왜 지금 문단 1~2개"],
      "why": [
        {"area": "산업", "text": "..."},
        {"area": "일", "text": "..."},
        {"area": "생활", "text": "..."}
      ],
      "glossary": [{"term": "용어", "desc": "쉬운 풀이"}],
      "think": ["더 생각해 볼 질문 1~3개"],
      "notes": ["클리핑과 원문이 다른 점 등 (없으면 빈 배열)"],
      "sourcesRead": [{"name": "매체명", "url": "원문 URL", "publishedAt": "YYYY-MM-DD", "note": "인용 출처 등(선택)"}]
    }
  ]
}
```

- `articles`는 그날 `newsItems`와 같은 개수·같은 `order`.
- `glossary` 2~4개, `why`는 산업·일·생활 3칸.
- JSON만 저장한다. 다른 파일은 건드리지 않는다.
