앤트로픽, '클로드 십' 베타 출시

앤트로픽이 AI가 쓴 코드의 검토·수정·승인을 자동화하는 '클로드 십'을 베타로 내놨습니다.

무슨 일인가

앤트로픽은 23일(현지시간) 기존 '코드 리뷰'에 수정 도구 'PR 스튜어드'와 승인 도구 '클로드 어프루벌스'를 연결한 '클로드 십'을 공개했습니다. 코드 리뷰는 정식 제공이고, 나머지 두 도구는 공개 베타입니다.

코드 리뷰는 변경 사항과 주변 코드를 분석해 검증된 지적을 PR에 남깁니다. PR 스튜어드는 자동 검사(CI) 실패, 코드 충돌, 수정 요청에 대응하고 바꿀 때마다 변경 내용과 되돌리는 방법을 설명하며, 직접 승인·병합은 하지 않도록 설계됐습니다. 클로드 어프루벌스는 저장소의 승인 정책에 따라 팀이 허용한 일상적 변경은 클로드가 승인하고, 별도 검토가 필요한 작업은 사람 승인을 요구하도록 설정할 수 있습니다.

깃허브 저장소를 쓰는 클로드 팀·엔터프라이즈 조직이 대상입니다. 에이전트 사용료는 구독에 포함된 사용량과 별개로 토큰 사용량만큼 청구되고, 승인 정책용 분류 모델과 코드 리뷰에도 비용이 듭니다. 데이터 보관 제로(ZDR), HIPAA 대응 설정, 고객 관리 암호화 키를 쓰는 조직은 쓸 수 없습니다.

배경 — 왜 지금

앤트로픽은 클로드 코드 팀에서 대부분의 코드를 클로드가 쓰고 있다며, PR을 올린 뒤의 검토·승인 작업도 코드 작성과 같은 속도로 하는 것이 목표라고 밝혔습니다. 개발자는 클로드 코드의 '/ship' 명령으로 변경을 올리고, '@claude'로 지시하거나 '@claude stop'으로 멈출 수 있습니다.

관리자는 적용 저장소, 검토 수준, 실행 시점, 비용 한도를 정할 수 있고, 앤트로픽은 처음에는 승인 판단 결과만 확인하는 관찰 모드로 쓰기를 권했습니다. 실제 병합은 깃허브 브랜치 보호 규칙을 따르지만, 사람 승인을 요구하지 않는 정책에 자동 병합을 함께 켜면 사람 개입 없이 병합될 수 있습니다.

왜 중요한가

산업

AI가 코드를 빠르게 쓰면서 병목이 '사람의 검토'로 옮겨 가고 있습니다. 검토·승인까지 자동화하는 도구 경쟁이 본격화할 수 있습니다.

일

사용량만큼 비용이 붙는 구조라, 도입 전에 비용 한도와 어떤 변경을 AI가 승인해도 되는지 정책부터 정해 두는 것이 중요합니다.

생활

우리가 쓰는 앱의 업데이트 일부가 사람보다 AI의 검토를 더 많이 거치게 될 수 있습니다. 그만큼 안전장치 설계가 중요해집니다.

어려운 말 풀이

PR(풀 리퀘스트)
코드 변경을 본 프로젝트에 합쳐 달라고 요청하는 단위로, 보통 동료가 검토한 뒤 합칩니다.
병합
검토가 끝난 코드 변경을 본 코드에 실제로 합치는 일입니다.
데이터 보관 제로(ZDR)
AI 서비스가 고객 데이터를 처리 후 저장하지 않도록 하는 설정입니다.

더 생각해 볼 점

  • 어떤 종류의 코드 변경까지 AI 승인에 맡겨도 괜찮을까요?
  • 검토까지 AI가 하면, 문제가 생겼을 때 책임 소재는 어떻게 정해야 할까요?
