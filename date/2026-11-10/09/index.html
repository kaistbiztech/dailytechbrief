학습 데이터 0.1%만 오염돼도 에이전트에 원격 코드 백도어 심김

사전 학습 데이터의 0.1%만 오염시켜도 AI 에이전트에 원격 코드 실행 백도어를 심을 수 있고, 이후 학습으로도 잘 지워지지 않는다는 연구가 나왔습니다.

무슨 일인가

앤트로픽 등이 참여한 공동 연구진은 10월 27일 아카이브(arXiv)에 '사전 학습 데이터 오염을 통한 에이전트 백도어' 논문을 공개했습니다. 큐원3 구조로 0.6B·1.7B·4B(매개변수 6억·17억·40억 개) 모델을 처음부터 학습시켜 명령줄 에이전트로 만들고, 학습 데이터의 0.1%를 오염시켰습니다.

4B 모델은 파일 경로에 특정 문자열이 있을 때 답 하나 기준 50.9%, 같은 문제에 답 32개를 만들게 하면 92.7% 확률로 공격자가 원하는 명령을 만들었습니다. 모델이 클수록 성공률이 높았고(0.6B 13.1%, 1.7B 51.9%), 오염 비율을 0.0005%까지 낮춰도 일부 성공 사례가 나왔습니다.

오염 뒤 깨끗한 데이터로 지도 미세조정(SFT), 선호도 최적화(DPO), 강화학습을 거쳐도 백도어는 사라지지 않았고, 일반 작업 성능은 정상 모델과 거의 같았습니다.

배경 — 왜 지금

기존 공격은 개발사 내부 시스템에 접근해야 했지만, 이번에는 공개 웹 문서만 조작해도 가능하다는 점이 다릅니다. 연구진은 커밋 메시지나 운영 매뉴얼처럼 보이는 문서에 '이 조건이면 이 명령을 실행한다'는 관계를 적어 넣는 '선언형 오염'을 썼고, 정상 문서와 구별이 어렵습니다.

수치는 악성 명령을 '만들어 냈는지'를 잰 것이지 실제 시스템에서 악성코드 실행에 성공한 비율은 아니며, 실험은 4B 모델까지만 했습니다.

왜 중요한가

산업

웹에서 모은 데이터로 학습하는 모든 모델이 영향을 받을 수 있어, 학습 데이터 출처 관리가 더 중요해질 수 있습니다.

일

연구진은 데이터 검증, 샌드박스, 최소 권한, 명령 허용 목록, 중요 작업의 사람 승인을 권했습니다. 에이전트에 명령 실행 권한을 주는 팀이라면 먼저 점검할 만합니다.

생활

일반 성능 시험으로는 드러나지 않는 문제라, 내 컴퓨터에서 명령을 실행하는 AI 도구는 권한을 좁혀 쓰는 습관이 도움이 될 수 있습니다.

어려운 말 풀이

백도어
평소엔 숨어 있다가 특정 신호(트리거)에만 작동하도록 몰래 심은 동작입니다.
원격 코드 실행(RCE)
공격자가 멀리서 남의 컴퓨터에 원하는 명령을 실행하게 만드는 공격입니다.
샌드박스
프로그램을 외부와 격리된 공간에서만 돌게 해 피해가 퍼지지 않게 하는 환경입니다.
pass@32
같은 문제에 답을 32번 만들게 해 그중 하나라도 성공하면 성공으로 세는 측정 방식입니다.

더 생각해 볼 점

  • 에이전트의 편리함과 실행 권한 제한 사이에서 어디에 선을 그어야 할까요?
