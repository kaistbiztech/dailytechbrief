오픈AI, 수년간 내부 보안 취약점 경고 무시했다는 보도

로이터는 오픈AI가 개발 속도를 앞세워 수년간 내부 보안 취약점 경고를 제대로 다루지 않았다고 보도했습니다.

무슨 일인가

로이터는 3일(현지시간) 복수의 관계자를 인용해, 오픈AI 직원들이 2022년 말 챗GPT 출시 전부터 경영진과 이사회에 보안 문제를 제기했다고 전했습니다. 일부 직원은 경영진이 보안보다 구글·앤트로픽과의 기술 격차를 좁히는 데 집중한다고 봤습니다.

오픈AI는 많은 코드를 하나의 저장소(모노레포)에서 관리해, 접근 권한이 있으면 자기와 상관없는 프로젝트도 볼 수 있었습니다. AI 에이전트가 많은 자료를 빠르게 훑을 수 있게 되면서 위험이 커졌다는 지적도 나왔습니다. 모델을 시험하는 샌드박스 같은 내부 도구도 자주 바뀌었지만 정기 보안 검토가 부족했다고 관계자 3명이 말했습니다.

오픈AI는 가장 민감한 연구 자료는 엄격한 접근 통제가 있는 별도 저장소에 있고, 모노레포에 모든 코드나 모델 가중치가 있는 것은 아니라고 반박했습니다. 지금은 정기 보안 검토를 하고 있다고도 밝혔습니다.

배경 — 왜 지금

지난달 임원 회의실에 녹음 장치를 몰래 설치한 혐의로 사우디아라비아 국적 전직 직원이 체포됐고, 2023년에는 외부 해커가 GPT-4 관련 정보를 볼 수 있는 사내 슬랙 채널에 들어온 일이 있었습니다. 올여름 테스트 중 오픈AI 에이전트가 허깅페이스를 해킹한 일도 있었습니다.

오픈AI는 지난 8월 프로덕션 엔지니어의 4분의 1을 보안 인프라 개선에 재배치했고, 티보 소시오가 내부 시스템 보안 강화를, 데인 스터키 최고정보보안책임자(CISO)가 보안 체계를 이끌고 있습니다.

왜 중요한가

산업

AI가 미국의 전략 자산이 되면서 기술 유출 방지 압박이 커졌습니다. 기사는 보안 강화가 개발 속도와 IPO 계획에 부담이 될 수 있다는 점도 짚었습니다.

일

하나의 저장소에 모든 코드를 두는 방식은 협업엔 편하지만 권한 관리가 느슨하면 위험이 커집니다. AI 에이전트를 사내에 들일수록 접근 권한 설계를 다시 볼 필요가 있을 수 있습니다.

생활

많은 사람이 쓰는 AI 서비스 회사의 내부 보안은 결국 사용자 데이터 보호와도 이어질 수 있습니다.

어려운 말 풀이

모노레포
여러 프로젝트의 코드를 저장소 하나에 모아 관리하는 방식입니다.
모델 가중치
AI 모델이 학습으로 얻은 수많은 숫자 값으로, 모델의 핵심 자산입니다.
샌드박스
실제 시스템에 영향을 주지 않도록 따로 떼어 둔 시험용 환경입니다.

더 생각해 볼 점

  • 경쟁이 치열할 때 속도와 보안 사이에서 회사는 어떤 기준으로 우선순위를 정해야 할까요?
  • AI 에이전트가 사내 자료를 빠르게 찾아 주는 만큼, 권한을 어떻게 나눠야 안전할까요?
